# Core detector integration progress

The detector imports the merged core contracts directly. `DetectorUnavailable` subclasses `ModuleUnavailable`; public `detect(site_id, window, history)` returns an actual `DetectionResult` and canonical `SeriesForecast` rows, including DNS keys with colons. Forecasts stay in memory; the detector does not write to the shared forecast table.

Gate 2 startup now uses `prepare_detector(cases_dir, out)` to read only TRAIN and VALIDATION packs and create a versioned feature-only JSON artifact. It validates safe paths, split names, IDs, seeds, time bounds, labels, and numeric feature matrices. TRAIN labels are classifier targets; anomaly fitting uses varying raw normal TRAIN metrics (constant metrics are excluded since they cannot define a continuous density); only the first three normal VALIDATION snapshots are scored for the reference distribution. No TEST metadata or observations are loaded, and the artifact has no SDK object or credential.

`configure_detector(artifact, settings=None, backend_factory=None)` validates and fits a real cloud/local provider, then caches it for public detection. `detect()` reuses the backend across calls and rejects an unprepared real backend before making provider inference calls. Explicit fixture injection remains available to offline contract tests and stays labeled `mode="mock"`. The Gate 2 anomaly reference uses a fixed seeded feature ordering and CPU density noise; it restores the extension RNG reference and PyTorch CPU RNG state after each score. The fixed 0.7 cutoff and three-sample reference support integration plumbing only; they are not accuracy or production-threshold claims.

Offline verification: all 45 detector tests pass, including Gate 2 artifact/setup, core contract, unprepared-provider and credential/timeout cache cases. After rebasing onto main d70f76f (Aun's CHR PR #6), the full repository suite passes 220 tests with three live tests deselected, including when unmocked Torch imports are blocked. Ruff, uv lock and diff checks pass.

The separate lead-run credentialed smoke returned a valid real TabPFN Cloud v3.5 DetectionResult, four forecast series with five points each, and unchanged forecast-table row counts (0 before/after). Setup took 271.7 seconds and detection 114.8 seconds. Predicted uplink_down differs from injected uplink_congestion: this is an integration pass, not an accuracy or latency pass.
