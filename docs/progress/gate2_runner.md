# Gate 2 runner progress

Added `eval/gate2.py` as a separate credentialed smoke CLI. It prepares a detector artifact only when absent, configures the actual provider once, seeds bounded normal `source=sim` history without replacing existing Site topology or duplicate metric keys, and calls public simulator injection for a current 15-minute scenario. It refuses an overlapping label rather than editing it. The ignored `data/generated/gate2/state.json` records its own label ID; a later run resumes only that exact active DB label, never another scenario. Re-seeding is locked per site, skips metric keys already present, and skips any recorded SIM scenario interval so it cannot add healthy data over an active or historical injected event.

`fetch_window(conn, site_id, start, end)` returns the actual core `MetricsWindow` from three site/source/time bounded queries. The runner separates strictly prior 60-minute history from a 30-minute current window, filters initial inference to the two documented probe targets and `ether1`, verifies actual cloud/local `DetectionResult` forecasts, and compares forecast-table row counts around detection. Reports include actual first/last metric times because a one-hour seed may contribute only 30 minutes to the strictly prior context window.

Provider stdout/stderr stays in memory; report error chains redact known secret values, URI userinfo, bearer strings, and common token prefixes. It writes sanitized JSON plus Markdown. Offline fetch and state/resume tests pass. No provider or database calls were made during implementation. Lead owns the separate credentialed execution after the code is reviewed.

Lead execution on 2026-10-18 passed the real-provider contract smoke. The report records four five-point cloud series, unchanged forecast rows, setup/detection timings, and the cause mismatch rather than claiming production quality. Existing live home-lab telemetry and topology were outside the runner's site scope; no migration was run.
