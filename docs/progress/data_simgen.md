# B2 data and simulator handoff

## Scope

Implemented `packages/simgen/`, three-site topology/scenario/message fixtures under `data/`, and the train/validation/test case generator in the package CLI. No shared core schemas, Settings, Cause model, or database schema were created. Generated and fetched Parquet/JSON files remain ignored.

## Interfaces for detector work

- `netcortex_simgen.simulator.generate(days=1, seed=42, start=None, scenario_type=None, duration_min=15, site_id=None, normal_only=False, hours=None)` returns `(probe_df, iface_df, labels)`.
- `inject_frames(site_id, scenario_type, duration_min=15, seed=42, start=None)` returns fixture DataFrames and one plain dictionary label. It is an internal simulator helper, not the shared core interface.
- `generate_supplemental(labels, *, start, end, seed=42, site_ids=None)` returns continuous experimental DNS, subscriber, and backhaul samples separately from core-shaped frames.
- `eval/cases/{train,validation,test}/{case_id}.json` sidecars point to sibling `-probe.parquet`, `-iface.parquet`, and `-supplemental.parquet`. Sidecars carry case/split/seed/site, event bounds, `as_of`, history window, expected label, and observation paths. For `n=80`, each split has 80 balanced cases (10 normal and 10 per cause). The test split is held out; train and validation are separate windows and seed ranges.
- CLI `inject` saves fixture rows at the deterministic simulator time base (default `2026-10-12T00:00:00Z`, single-cause event at +2h); `replay` merges persisted fixture files with generated rows in time order. This is offline fixture playback, not router/runtime injection. `inject_frames(..., start=...)` accepts a different synthetic start.

## Implementation and validation

Three configured sites model primary/backup capacity, targets, subscribers, and wireless backhaul. Seeded NumPy generates 10-second ping and 30-second interface observations. Pakistan-local time shapes daily demand; output timestamps are UTC. Congestion, heavy-user, uplink-down, and wireless-interference scenarios affect interface telemetry as well as pings. Gateway pings remain healthy during upstream congestion/down events. Total ping loss is exactly 100%, with RTT/jitter absent when no packets arrive. Calibration reads mapped target/hour and role/hour values where available; illustrative defaults are marked in provenance.

RIPE parsing accepts the API's `result` packet array and preserves measurement/probe/ASN/target/time provenance. Probe and public-measurement discovery is dynamic. UTC-day requests filter to selected probe IDs; cache keys include those IDs. Requests have 15-second maximum per-request timeout, five-second connect timeout, 300-second default overall deadline, 8 MiB response cap, 10,000 result-row daily cap, bounded pagination, and a 0.25-second request gap even after failures. Partial coverage stays in the fetch report without imputation.

The integration checkout now contains 11,819 actual public RIPE records covering 2026-10-11 through 2026-10-17: probes 7613, 7764, and 7812 across three ASNs; dynamically discovered measurements 1001 and 1004. Measurement 1001 covered all seven days. Measurement 1004 covered four days, with three daily requests timing out. `data/ripe-baseline-summary.json` and the ignored raw Parquet are parent-owned and were preserved. [The calibration report](../../data/calibration-report.md) is generated from that Parquet and reports target and role medians, hours, provenance, uncertainty, and gaps. Both observed targets are root-DNS reachability checks, not DNS lookup timing. The committed exact-target role map labels those observed paths as `public_dns_reachability_proxy`; transfer remains off unless `simgen calibrate --target-role-map data/ripe-target-roles.json --allow-role-proxy` is explicitly run. When enabled, the proxy is restricted to unmatched configured public DNS targets (`1.1.1.1`, `8.8.8.8`); exact target calibration takes precedence, and generated metadata records the source, destination, and unproven route equivalence. Gateway, upstream-hop, game-server, and DNS resolution timing never use the proxy.

Validation in the integration checkout: 20 simgen offline tests pass and root-config Ruff passes. A wheel build and outside-checkout generation were validated in the original isolated worktree. Calibration was run against the actual 11,819-row Parquet with the committed explicit source-role map and `--allow-role-proxy`; it wrote ignored `data/calibration.json` and `data/calibration-report.md`. A subsequent normal-only generate run wrote `data/generated/generation_metadata.json`; it reports proxy use only for `1.1.1.1` and `8.8.8.8`, leaving gateway, upstream-hop, and game target defaults illustrative. `simgen calibrate --mock` exits clearly and creates no calibration from invented values.

## Boundaries

DNS/subscriber/backhaul records are separate experimental supplemental data, continuously generated for healthy and labeled periods so their mere presence does not leak class. They are not loaded into draft core tables; DNS timing, subscriber privacy/evidence, and interface role contracts remain pending Aun. Public `inject(...)->ScenarioLabel` lazily imports actual `netcortex_core` exports and raises an explicit unavailable-contract error when absent. Even with core importable, lifecycle creation is gated pending approval. DB load/replay persistence refuses to write until keys and transaction semantics are confirmed; mock load reads and validates source rows. No database write or working live injection is claimed.
