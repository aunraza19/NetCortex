# Detector flow and API

`build_features(probes, interfaces, *, site_id, as_of, target_roles=None, source_roles=None)` checks required columns, aware UTC cutoff, site isolation, timestamp validity, and source boundaries. If source fields are present, each frame must use one source and both frames must agree. It returns a one-minute-indexed pandas frame with past-only values, lags, rolling summaries, and UTC calendar fields. With no role mapping, target and interface IDs remain distinct under `target:` and `interface:` prefixes. `detect()` maps either default-prefixed or explicitly role-mapped raw feature names through the core `series_key()` helper, preserving colons in DNS target names. It raises `ValueError` for malformed or mixed-site inputs.

`run_engine(probes, interfaces, *, site_id, as_of, backend, history_start=None, config=None, training_features=None, training_labels=None, anomaly_threshold=None)` is the independently testable inference API. It returns a plain dictionary with anomaly/cause/forecast/evidence fields, status, provenance, and a supplemental-use flag. Missing, stale, or sparse observations return `availability="unavailable"` and a null anomaly outcome. Invalid backend causes and provider failures are errors (`DetectorUnavailable`), not healthy results. The backend is injected; this function does not silently choose a mock.

`detect(site_id, window, history)` accepts actual core `MetricsWindow` objects. It combines their probe/interface rows, runs the current window through `as_of`, and calls the provider selected by shared `Settings()`. It maps in-memory forecasts to core `SeriesForecast`/`ForecastPoint` objects with canonical series keys, preserving DNS target colons; an unrecognized forecast metric fails explicitly instead of disappearing. Missing/stale measurements and provider failures raise `DetectorUnavailable`, a `ModuleUnavailable` subtype. It never writes forecast rows. The detector API does not accept labels or normal reference scores; Gate 2 preparation will provide detector-owned state from TRAIN and normal VALIDATION data without using TEST labels at inference. Fixture backend output is marked `mode="mock"` and `model="fixture_persistence"`.

`TabPFNBackend("cloud" | "local")` supplies real provider calls. Cloud uses `tabpfn_client`, `TABPFN_TOKEN`/`TABPFN_API_KEY` or an injected key, `set_access_token`, v3.5 factories, and a 30-second client timeout. Local uses TabPFN classifier/regressor and `ModelVersion.V3_5`. Regressors request `output_type="quantiles"` for quantiles `[0.1, 0.5, 0.9]`; the bands are sorted before reporting. The unsupervised extension is fit on normal TRAIN data; low log-likelihood is normalized against normal VALIDATION scores. Regressors use lag/calendar predictors and shifted targets; only raw RTT, loss, and utilization are forecast targets. Horizon-expanded fit rows are capped at 2,048 with deterministic per-horizon sampling. Quantile-first SDK responses are converted horizon-wise, and nonfinite, unordered, out-of-range, or invalid-time forecasts fail explicitly. Missing packages, key, model download, GPU/runtime support, and inference failures are explicit. No network request is made by the unit tests.

`FixtureBackend` is an explicit offline fixture only. Its provenance is embedded in outputs. It supplies deterministic persistence bands and simple visible rules to verify evaluator wiring, not product inference.

`python eval/run.py --mode mock|cloud|local [--cases eval/cases] [--out eval/results/detector.md] [--limit N]` consumes each split directory's JSON sidecars and Parquet probe/interface observations. It verifies split IDs, seeds, and event intervals do not overlap and observation paths cannot escape split directories. TRAIN sidecar causes are labels for classifier fitting only; VALIDATION calibrates the anomaly cutoff; TEST produces metrics. It records actual denominators and unavailable results. Aun's `investigate()`, template schema/parameter validation, and CHR check are reported unavailable until implemented and machine-readable.

The runner writes Markdown. `eval/results/agent.md` follows the same principle: agent, parameter, and router-check metrics remain unavailable unless those real APIs return recorded results; the runner does not make substitute claims.
