# Evaluation flow and CLI

`python eval/run.py` defaults to `--mode mock`, cases under `eval/cases/`, and report `eval/results/detector.md`. Options: `--mode mock|cloud|local`, `--cases PATH`, `--out PATH`, `--limit N` (for a short fixture smoke run). Cloud/local require optional model dependencies and cloud uses `TABPFN_TOKEN` or `TABPFN_API_KEY`. Provider failure is recorded per test case; missing required case files or split leakage aborts the run.

For each case, the runner loads only the referenced probe and interface Parquet files, builds a feature snapshot through its aware UTC `as_of`, and uses TRAIN labels solely as cause targets. It runs validation first to derive the threshold using the union of scored normal detection windows per site, then calls the detector on test cases. Positive windows and training history do not increase the false-alert budget; the same exposure definition is used for reported false alerts/site-day. Results report detector provenance, available/unavailable counts, cause accuracy, event precision/recall with denominators, and elapsed time.

The initial B9 runner cannot call Aun's `investigate()` because the core/agent interface is absent from this worktree. Optional injected investigator, parameter-validator, and CHR-check callbacks produce metrics only from actual returned records; without them the runner writes `template_accuracy`, `valid_params_rate`, and `chr_dry_run_pass_rate` as unavailable with reasons. Detection delay is unavailable from single snapshots. It does not infer parameters from labels, count a fake CHR pass, or turn a missing backend into a successful run. `eval/results/agent.md` is reserved for a real investigation integration and is not fabricated here.
