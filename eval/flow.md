# Evaluation flow and CLI

`python eval/run.py` defaults to `--mode mock`, cases under `eval/cases/`, and report `eval/results/detector.md`. Options: `--mode mock|cloud|local`, `--cases PATH`, `--out PATH`, `--limit N` (for a short fixture smoke run), `--with-agent`, and `--chr-dry-run`. Cloud/local require optional model dependencies and cloud uses `TABPFN_TOKEN` or `TABPFN_API_KEY`. Provider failure is recorded per test case; missing required case files or split leakage aborts the run.

For each case, the runner loads only the referenced probe and interface Parquet files, builds a feature snapshot through its aware UTC `as_of`, and uses TRAIN labels solely as cause targets. It runs validation first to derive the threshold using the union of scored normal detection windows per site, then calls the detector on test cases. Positive windows and training history do not increase the false-alert budget; the same exposure definition is used for reported false alerts/site-day. Results report detector provenance, available/unavailable counts, cause accuracy, event precision/recall with denominators, and elapsed time.

`--with-agent` passes the actual detector result as a core `DetectionResult` and the case's probe/interface observations as `MetricsWindow` to `netcortex_agent.agent.investigate`. The returned `IncidentReport` is scored for likely cause and template, and its template parameters pass through `netcortex_fixes.validate`. `--chr-dry-run` additionally invokes `netcortex_fixes.dry_run` using the configured CHR client; it requires `--with-agent`, CHR credentials, and a reachable test router. Both options are opt-in because they need external services; the CHR option applies then rolls back a test config. Without these runs, their metrics remain unavailable. Detection delay is unavailable from single snapshots. Expected labels never supply agent inputs or inferred parameters.

## Gate 2 credentialed smoke

Run `.venv/Scripts/python.exe eval/gate2.py --cases eval/cases --artifact data/generated/gate2/training.json --out eval/results/gate2.json` only for the separately authorized credentialed Gate 2 check. It prepares the data-only TRAIN/VALIDATION artifact if absent, configures a real cloud/local backend once, preserves an existing `north-tower` Site, and seeds only missing bounded normal SIM rows before calling public `inject()` for 15 minutes. An existing overlapping scenario is an error and is never replaced.

After one 12-second cadence wait, the runner fetches source=`sim` metrics from the last 30 minutes and strictly prior 60-minute context. The one-hour seed may supply only 30 minutes inside that past context; the report records actual first/last metric times for each stream. Initial inference is limited to probes `1.1.1.1` and `dns:1.1.1.1` and interface `ether1`. The helper `fetch_window(conn, site_id, start, end)` runs three bounded core-column queries and returns an actual `MetricsWindow`. Public `detect()` must return real cloud/local DetectionResult with five ordered future points per canonical series. Forecast row counts are compared before/after detect. Vendor stdout/stderr is held in memory; the output contains sanitized results and error chains only. JSON and a companion Markdown report are written to the requested path. This smoke measures plumbing only, not production accuracy or latency.
