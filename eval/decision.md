# Evaluation decisions

- Consume simulator-generated `train`, `validation`, and `test` directories as-is. Each case JSON names separate probe/interface/supplemental Parquet observations and expected sidecar labels. Expected cause becomes the training `y` only for TRAIN and scoring truth only for held-out cases; expected params/template are never features.
- Reject overlapping case IDs, seeds, or event intervals across splits; reject observation paths that escape their split directory. The simulator generator is responsible for its 80-per-split, balanced causes design; evaluator records actual counts instead of assuming the requested count.
- Fit the classifier only from TRAIN feature snapshots. Fit unsupervised models from normal TRAIN rows; use normal VALIDATION scores for empirical score calibration and select the threshold by F1 subject to a false-alert budget computed from unioned normal detection-window exposure per site. Positive validation windows do not increase exposure. The held-out TEST split is not used to fit, select, or tune.
- `--mode mock` is an explicit fixture backend used to check data wiring and report generation. Its outputs are never described as TabPFN accuracy. `cloud` and `local` use actual provider adapter code and preserve unavailable/error statuses.
- False alerts/site-day uses the union of scored normal detection-window exposure per site. Cause accuracy and event precision/recall include explicit denominators. Missing agent investigation, template validation, and CHR infrastructure are `unavailable`, never 0% or assumed passes. Per-case latency is recorded for completed detector runs; event delay is unavailable because each case is a single as-of snapshot. Injected investigator, parameter-validator, and CHR-check callbacks are measured only from actual returned records.
- Supplemental DNS/subscriber/backhaul Parquet remains experimental and is not read by this evaluator. Core DNS RTT is not treated as DNS-resolution evidence, and aggregate counters do not identify a subscriber.
