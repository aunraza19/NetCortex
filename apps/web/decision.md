# Web dashboard decisions

- **Next.js App Router with TypeScript and Tailwind CSS v4.** This matches the build brief and current Next.js installation guidance. Versions are pinned in `package.json` and `package-lock.json`; Next.js 16.4.2 is the stable version selected during this build. Tradeoff: the App Router and React 19 are newer than the root CI runtime, so the root pipeline must use supported Node 20.9+ (the requested CI Node 22 is suitable).
- **Fixture-first typed transport boundary.** `Transport` centralizes sites, incidents, metrics, injection, decisions and stream subscription in `lib/transport.ts`. `NEXT_PUBLIC_API_MODE` selects fixture or live mode at build/runtime. This makes the interface work offline while keeping live errors visible. Fixture DTOs are provisional and do not claim to implement OpenAPI. Regenerate or replace types after Aun publishes the API schema.
- **Exact draft endpoints from the partner plan.** Live requests use `/sites`, `/metrics?site_id&from&to&series`, `/incidents?status`, `/incidents/{id}`, `/incidents/{id}/voice`, `/incidents/{id}/approve`, `/incidents/{id}/reject`, `/demo/scenarios`, and `/stream`. The provisional metrics series is `probe:1.1.1.1:rtt_ms`. Decision POST responses are acknowledgements only, followed by a GET of the incident; injection POST responses only confirm queued diagnosis and never become an incident record. Field mappings need validation against the eventual OpenAPI contract.
- **Explicit fixture provenance.** Persistent `Demo: replayed data` badge appears in every route. Fixture dry-run and apply states say they are simulated; mock mode does not contact a router. The voice control displays an unavailable message because there is no real bundled audio or voice endpoint contract yet.
- **Simulator topology source with a fixture boundary.** Subscriber counts, primary capacities and backup capacities in `lib/fixtures.ts` mirror the canonical `data/sites.yaml`: North Tower 120 / 180 Mbps / 80 Mbps backup, Market Cafe 48 / 100 Mbps / no backup, and East Relay 165 / 250 Mbps / 100 Mbps backup. The dashboard’s health, utilization, latency and loss remain illustrative replay samples, not live simulator readings. Keeping the split avoids contradicting topology while preserving the demo-only telemetry disclosure.
- **Approval guard and confirmation.** Approval is enabled only for `awaiting_approval`, `dryRun === passed`, a non-`none` template and non-empty commands. Rejection remains possible for `open` or `awaiting_approval`. Radix confirmation dialogs, a busy flag and transport state guards prevent accidental or repeated decisions. Fixture approval visibly advances through applying, verifying and then resolved or rolled back; fixture rejection becomes rejected.
- **Local incident fixture store.** Injection creates a browser-memory incident for actionable scenarios and a no-router-change message for normal/notify-only scenarios. Market Cafe has no configured backup, so an uplink-down replay there is notify-only. Queue, DNS and failover rollback commands match their proposed changes. Simulated CHR results are labeled as fixture-only. A refresh resets this memory state. There is no persistence claim.
- **SSE refresh strategy.** Named `metric`, `incident.opened`, `incident.updated`, `fix.tested`, and `fix.applied` events trigger a data refetch. `lastEventId` values are deduplicated within one EventSource connection; `onerror` and a subsequent `onopen` request refreshes as the stream recovers. Cleanup removes listeners and closes the source. Event envelope and ID replay semantics await Aun's confirmation.
- **Pakistan time without hydration mismatch.** The overview renders a placeholder for the live clock and formats timestamps after mount with `Intl.DateTimeFormat` and `Asia/Karachi`. This avoids server/client locale mismatch.
- **Settings deferred.** The settings route explains that configuration is managed by the service and does not show a fake save action while the Settings/API contract is unresolved.
- **Sentry SDK is optional and unverified.** Browser and Node configuration only initialize when a DSN exists. The installed SDK's current options omit `sendDefaultPii`; no PII capture is enabled in this app. Aun/lead must provide a project DSN and verify delivery before claiming monitoring is connected. No project provisioning or external event was done here.
- **Render runs SSR as a Node service.** The package `start` script runs `next start` and accepts Render's `--hostname`/`--port` arguments. `output: 'standalone'` is omitted because Next.js documents that `next start` cannot be used with standalone output. Static export would not match the requested Render SSR deployment.
- **OpenAPI types are generated only from a supplied schema URL.** `npm run api:types` requires `OPENAPI_URL`, downloads it with a ten-second deadline, checks it is an OpenAPI object, and writes a separate `lib/generated/openapi.d.ts`. There is no schema in this branch, so no generated types are claimed.
- **Unpatched development-tool advisory retained rather than forcing a breaking downgrade.** `npm audit` currently reports five high findings that all resolve to the same transitive `braces@3.0.3` advisory via `micromatch@4.0.8` → `fast-glob@3.3.1` → `@next/eslint-plugin-next@16.4.2` → `eslint-config-next@16.4.2`. The advisory is stack-exhaustion from deeply nested brace patterns; it lists no patched release, and the npm registry has no `braces` version beyond 3.0.3. `npm audit fix --dry-run` offers only the incompatible major downgrade to `eslint-config-next@14.2.35`, so no override or forced downgrade was applied. The dependency is in the lint toolchain only, not production dependencies; `npm audit --omit=dev` reports zero vulnerabilities. Recheck when upstream publishes a compatible fix. See [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) and [upstream braces discussion](https://github.com/micromatch/braces/issues/84).
